## Real regressions surfaced (the headline value)

The whole point of running 61 md playbooks was to exercise the codebase end-to-end. Here are the **8 concrete regressions** the exercise found that aren't in any one ticket:

1. **L0 hook download-directory rule not active** — `scripts/verify-l0` and `scripts/verify-l3-sim` both fail because synthetic `wget` PreToolUse payloads return `allow` without emitting the expected `先检查下载目录` anchor. Either the rule isn't seeded into the live knowledge store, or the synthetic payload format doesn't match the matcher's PreToolUse contract anymore.

2. **Stale test paths after M5 refactor** — `scripts/hook-prompt-verify` references `format-snapshot.test.ts` and `keyword-matcher-meta-cmd.test.ts`; neither file exists post-M5.

3. **Vendored skill preamble divergence** — `scripts/verify-vendored-skills` finds 3-line preamble bin-lookup-order differences between `.claude/skills/{design-shotgun,design-html}` and the corresponding `.codex/skills/`. YAML frontmatter is identical; the divergence is in the bash preamble alone.

4. **`--help` baseline outdated** — `scripts/judge-first-run` J6 fails because `docs/baselines/help-output.txt` predates the `teamagent pack` subcommand suite (4 lines added since baseline capture).

5. **Postinstall `--help` anchor missing** — same playbook J3 only hits 5/6 anchors; the standalone `--help` token is no longer emitted in the post-install message.

6. **Duck mode not wired into `stats` / `postinstall` output** — `scripts/duck-mode-verify` finds zero `呷呷|鸭鸭|>ω<` lines when `TEAMAGENT_EXPLAIN_LIKE_CEO_DUCK=1` for either of those output paths. Feature is hooked elsewhere but not these two surfaces.

7. **`validateLevel0` API drift** — `docs/features/rule-quality/run-judge` runner passes `{rule}` and reads `{valid, errors}`, but `validateLevel0` now expects `{entry, projectStack}` and returns `{ok, failed_checks}`. Result: 10/10 clean rules misclassified as defective.

8. **`verify-codex` jq path-shape assertion** — playbook checks for absolute SKILL.md path in `codex debug prompt-input` output; Codex now uses `r0/canary/SKILL.md` shorthand. The skill **is** correctly registered; the playbook's assertion was written against a deprecated path shape.

## One playbook spec bug (not a code regression)

- **`scripts--verify-codex-raw-chat` (Wave A)** §V3 SKIP rule says "verdict = SKIP only if `managed_block_present == false`". The TEAMAGENT-managed block is supposed to be present (auto-regenerated by `pnpm teamagent compile`). The §V3 condition is inverted; this is the only Wave A FAIL and represents a playbook-bug, not a regression.

## Environment gaps (the SKIP-INFRA cluster)

23 SKIP-INFRA verdicts collapse to **two root causes**:

1. **Worktree has no `node_modules`** (most C-2 / C-3 / C-4 SKIPs) — pnpm workspace links missing under `.claude/worktrees/mdplaybook/node_modules/`. Cross-package imports (`@teamagent/types`, `@teamagent/core`) fail at module resolution. Fix: `pnpm install` inside the worktree, or arrange a fallback symlink to the main checkout's `node_modules/.pnpm/`.

2. **MiniMax API endpoint timing out** (Wave B multi-tool, all `claudefast -p` steps in C-1/C-2/C-4) — `api.minimaxi.com/anthropic` reachability was 45–90s during this test pass. Any playbook that dispatches `claudefast` for live LLM grading was pre-empted to SKIP-INFRA without burning the budget.

A handful of items are also **SKIP-UNSAFE** rather than -INFRA:
- `team-sharing-probe/run-judge` real-run mode (would push to a real GitHub remote — only dry-run is safe).
- `ab-benchmark/run-judge` (20 sequential `claudefast` calls; both API down and token-budget unsafe).

## What this confirms about the md-playbook rule

The exercise is also the first end-to-end test of the project rule
"third-party judge harness forbidden fixed scripts; MUST use md
playbook" (`docs/HOWTO-PLAN-PR.md` § 3b, `docs/PR-PLAN.md` § ③). What
the 61-playbook pass tells us:

- **The rule scales**: a sonnet subagent can dispatch a playbook without re-implementing it, and a separate LLM judge reading only `judge.json` + `evidence_dir` produces honest verdicts (the agents repeatedly emitted SKIP rather than fabricating PASS — see the self-report blocks in every wave).
- **The rule is more diagnostic than the original `.sh`**: 8 real regressions surfaced, plus 1 playbook spec bug. The original 61 `.sh` files were running on someone's laptop and either (a) drifted silently or (b) weren't being run on every PR. By translating each into a `judge.md` we made re-dispatch a one-line `Agent`/`SendMessage` call.
- **Failed sections rerun by re-dispatching, not by editing scripts** (the rule's marketing pitch) — verified live: when Wave C-3's sonnet stalled past quota, I redispatched the 12-playbook batch directly without rebuilding the harness.
