# HookShell as the deepening of 8 bin-*.ts imperative shells; two-layer API; no new ports

We extract a new `HookShell` module into `packages/cli/src/hook-shell/` that absorbs the imperative wiring shared by all 8 hook channel binaries (`bin-pre-tool-use`, `bin-post-tool-use`, `bin-user-prompt-submit`, `bin-stop`, `bin-pre-compact`, `bin-session-start`, `bin-session-end`, `bin-updater`) — stdin JSON parse, three-database path resolution + `mkdirSync`, `DualLayerStore` + `SqliteEventLog` open/close lifecycle, `AttributionBus` injection, and the top-level "exit 0 never block harness" guarantee — into one `runHook` default-layer entry point plus one `runAdvancedHook` entry point that exposes opt-in escape hatches (`detached` self-spawn, `lock` file, `pipelineTimeoutMs`, `manualResources`) only for `bin-stop`-class heavyweight channels. The deepening is enforced by a TypeScript conditional type on `runAdvancedHook` that fails to compile when no `escape.*` field is provided, mechanically routing simple channels back to `runHook` rather than letting them stylistically pick the wrong layer. All `process.stderr.write("TeamAgent: ...")` user-visible text in the 8 binaries is replaced by `bus.emit({ kind, ... })` against a reshaped `AttributionEvent` (now a discriminated union by `kind` rather than a free-string `action`), and 2 hook handler factories (PreToolUse + PostToolUse — the only SDK-style `createXxxHandler(deps)` factories that existed in `packages/adapters/src/hook/claude-agent-sdk/`; the other six hook channels live as direct `bin-*.ts` imperative entries with no factory to sweep) are moved from `packages/adapters/` to `packages/core/` to fix a long-standing FCIS (Functional Core, Imperative Shell) violation that `pre-tool-use-sdk.ts` and its peer were doing pure logic in the adapter layer with only three impure call sites (`crypto.randomUUID()`, `new Date().toISOString()`, `process.env.TEAMAGENT_HOOK_ASCII_BOX`) that are now injected as deps. **No new ports are introduced**; in line with ADR-0005, all cross-seam dependencies use existing modules (`DualLayerStore`, `SqliteEventLog`, `AttributionBus`) directly, because LANGUAGE.md's "one adapter = hypothetical seam" rule rejects every new port the strict-P&A design alternative considered (`HookIOPort` / `ClockPort` / `HookProcessPort` would each have only one production adapter). The accepted trade-off: bin-stop's 632 lines drop to ~50 + the existing `commands/stop-pipeline.ts`, the 7 simple channels each drop below 35 lines, the 8-way duplicated `process.stderr.write` taxonomy collapses into one `AttributionEvent` discriminated union, and the cost is one `runAdvancedHook` opt-in API surface that 7 of 8 channels never see and one TS conditional type guarding it.

## Considered Options

- **(a) Single entry point `runHook(handler, opts)` with options union covering all channel concerns** — Rejected. Concentrates leverage but degrades reading: `RunOptions` becomes a union of `lockFile?`, `detachedArgvProbe?`, `maybeSelfSpawn?`, `timeoutMs?`, `requireField?` etc. across 8 different channels' needs, and a reader of `runHook(...)` can't tell which fields apply to their channel. Locality wins (one place for cross-cutting) but discoverability loses. The two-layer split preserves locality (still one shell) while making the simple-vs-complex choice mechanical via TS gate.
- **(b) Plugin / lifecycle-hook framework with 9 phases (`boot/readInput/parseInput/preHandle/handle/postHandle/writeOutput/shutdown/error`) and per-channel plugin lists** — Rejected. Maximizes flexibility for hypothetical future channels (MCP, Cursor — both NOT YET per `docs/features/multi-tool.md`) but at the cost of 9 phases × 20+ plugins = large interface surface, plugin-ordering bugs as a real failure class, and `ctx.state: Map` cross-plugin coupling that easily regresses to global mutable state. Over-engineering for 8 channels of which 7 are simple. If MCP / Cursor materialize, `runAdvancedHook` can absorb them via the same escape-hatch mechanism without the plugin framework.
- **(c) Strict ports & adapters (`HookIOPort` + `ClockPort` + `HookProcessPort` + `KnowledgeStorePort` + `PersistedEventLogPort`) with two adapters each (production + in-memory test)** — Rejected, in alignment with ADR-0005. Each new port would be either a hypothetical seam (the strict-P&A subagent's own self-critique acknowledged `ClockPort` and `HookIOPort.homedir()` as hypothetical, with only one adapter justified by current needs) or duplicate existing seams that already have port discipline (`AttributionBus`). The cost — 5 new port files + 6+ new adapter files + contract test suites + IDE noise — outweighs the leverage when the deps in question (`process.stdin`, `os.homedir`, `path.join`) are stable platform surface that production never replaces. The `manualResources` opt-out + `bus`-via-existing-port + direct-import of `DualLayerStore` / `SqliteEventLog` achieves the same testability with zero new ports.
- **(d) Big-bang single-commit migration of all 8 binaries plus AttributionEvent reshape plus FCIS sweep** — Rejected. `bin-stop.ts` (632 lines including `spawn detached`, lock file, scan cursor, 240s pipeline timeout, 7-step pipeline) is high-risk migration territory; combining it with simpler bins in one commit makes rollback granularity coarse and code review impossible. Incremental 16-commit split (HookShell skeleton with 0 callers → handler factory moves → reshape AttributionEvent → 7 simple bins canary-by-canary → bin-stop last → docs/ADR/lint cleanup) keeps each commit independently reviewable and revertable.
- **(e) Defer AttributionEvent reshape to a separate later PR** — Rejected after grilling. Decoupling (option γ in the grill) was the conservative choice; the user explicitly opted to fuse the reshape into this PR (max-power scope) so that the ~14-20 new `bus.emit(event)` call sites land with the final discriminated-union shape rather than writing throwaway `action: string` payloads that immediately become technical debt.

## Consequences

- **`packages/cli/src/hook-shell/` becomes the canonical location for hook lifecycle code.** All eight `bin-*.ts` files import either `runHook` or `runAdvancedHook` from this module. New hook channels (e.g., a future MCP channel) MUST use the shell, not write their own imperative-shell code.
- **Two hook handler factories live in `packages/core/src/hook/`, not `packages/adapters/`** (PreToolUse + PostToolUse — the only `createXxxHandler(deps)` factories that existed in adapters). The CLAUDE.md元约束 "Functional Core, Imperative Shell — `packages/core/` 禁止 import `fs` / `node:child_process`" applies to these factories now that they are in core; impurities (`crypto.randomUUID()`, `new Date()`, `process.env.X`) become injected deps (`idGen`, `now`, `formatStyle`). The adapter layer retains thin wrappers that bind production deps and re-export. **Other hook channels** (`user-prompt-submit` / `stop` / `session-start` / `session-end` / `pre-compact` / `updater`) had no `createXxxHandler(deps)` factory pattern in adapters — they were already imperative `bin-*.ts` entries — so commits 5-12 migrated them to use `runHook` / `runAdvancedHook` directly without an adapter→core handler move step.
- **`AttributionEvent` is a discriminated union by `kind`.** Adding a new event kind is a type-additive change (no breakage) but renaming or removing a kind is a breaking change requiring callsite migration. The `StdoutRenderer` exhaustiveness check (`switch (event.kind)`) becomes the contract that catches missed kinds at compile time.
- **`process.stderr.write` of user-visible text is forbidden in `packages/cli/src/bin-*.ts`.** A lint rule (custom shell check or ESLint rule) enforces this. Debug-only fallback logging (`teamagent <hook>: <error stack>`) remains allowed because it's an exception path, not user-facing system attribution.
- **`runAdvancedHook` requires at least one `escape.*` field via TypeScript conditional type.** A contributor reaching for `runAdvancedHook` without needing detached/lock/timeout/manualResources gets a compile error pointing them back to `runHook`. This makes the simple-vs-complex choice mechanical, not stylistic.
- **No new port interfaces are introduced by this PR.** In line with ADR-0005, the absence of two real adapters per cross-seam dependency means we direct-import existing concrete modules (`DualLayerStore`, `SqliteEventLog`, `InMemoryAttributionBus`). `AttributionBus` remains the only port the shell consumes, because it already has two adapters in spirit (`InMemoryAttributionBus` + `StdoutRenderer` rendering pipeline).
- **`docs/CONTEXT.md` gains three new terms under "Integration & shell": `Hook channel`, `HookShell`, `Hook handler`.** Without these, project docs that say "the 4 hook channels (PreToolUse / UserPromptSubmit / Stop analyze / AttributionBus)" — a phrasing that conflates the integration channels with `AttributionBus` itself — would remain ambiguous after this PR.
- **bin-stop's `spawn detached` re-entry guard, lock file, scan cursor, and 240s timeout machinery move into `runAdvancedHook`'s escape-hatch implementation** but the actual pipeline body (`runStopPipeline`: analyze → calibrate → compile → harvest → scan-errors → narrative-scan) stays in `commands/stop-pipeline.ts`. The shell handles lifecycle; the pipeline owns domain logic.
- **Walking Skeleton (`pnpm teamagent skeleton-demo`) must continue passing** at every milestone-end commit. Specifically, commits 1–4 (shell + handler moves + reshape, before bin migration) must not break skeleton-demo because skeleton uses `InMemoryAttributionBus` directly. Commits 5–12 (per-bin migration) must each leave skeleton-demo green.
- **Cross-PR ordering with ADR-0005 (`_archived/` ports)**: ADR-0005 PR merges first; HookShell PR rebases atop and confirms zero references to archived ports remain. If ADR-0005 is delayed, HookShell can still merge — they don't share files — but the `docs/CONTEXT.md` "no per-port hypothetical seams" discipline should be applied consistently between the two PRs.
- **POSTPR contract**: the fused PR is large enough that Codex review will likely surface P1/P2 issues; per `docs/PR-PLAN.md`, those must be fixed in this same PR via `PR-PLAN` + `TEAMWORK` parallelism, not punted to follow-up issues. Merge gate: CI green + no merge conflict + Codex silent or 👍.
